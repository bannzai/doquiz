# 方向性: doquiz

## 仮説

電子書籍 (主に Kindle) で文字の本を読む人は、読んだつもりで内容が残らず、ハイライトやメモを手で取るのも続かない。読んでいる間の画面を取り込んで本文を抽出し、読み終えた直後に読んだ範囲から理解確認のクイズを出せば、手間を足さずに理解を確かめられる。

## 判定基準

作り手の目的は収益で、配信先は App Store (2026-11-17 に bannzai が決めた。「決めたこと」の行)。課金は最初の版に入れ、1 週間のトライアルを付ける。課金の形は月額・年額のサブスクリプションと買い切りで、実装には RevenueCat を使う (どれも 2026-11-18 に bannzai が決めた)。継続のしきい値・打ち切り条件・公開前に打ち切る条件は、bannzai が 2026-11-18 に採った (https://github.com/bannzai/doquiz/issues/2 の本文の「続けるか・やめるかの基準」の表)。転換の条件の列は評価レポート (2026-11-17) の案のまま。値段は月額 500 円・年額 5,000 円・買い切り 20,000 円。1 週間のトライアルは月額と年額だけに付け、買い切りには付けない (どれも 2026-11-18 に bannzai が決めた。「決めたこと」の行)。購入もトライアルもしていない利用者は、読書を 20 回まで無料で使える (2026-11-19 に bannzai が決めた。2026-11-18 の「無料で使える範囲は置かない」を改めた)。目標の月間収益は bannzai が保留にしている。

| 指標 | 計測元 (skill / コマンド) | 継続のしきい値 | 打ち切り条件 | 転換の条件 |
| --- | --- | --- | --- | --- |
| 初回ダウンロード数 (14 日) | aso-analytics-explorer skill (App Store Connect の Analytics Reports API) | 30 件以上 | 2 回連続 10 件未満 | 製品ページの表示はあるのにダウンロードが少なければ、ストアの訴求 (スクリーンショット・説明文) の転換 |
| 課金の売上 (開発者取り分) | appstore-sales-report skill | 公開から 28 日で 1 件以上の購入 | 56 日で購入 0 件 | ダウンロードは継続のしきい値を超えるのに購入が 0 件なら、価格・無料で使える範囲の転換 |

公開前に打ち切る条件:

- 実機で Kindle・Apple Books・楽天 Kobo のどれも本文が取り込みに映らない
- 端末内モデルの 4K トークンに、クイズ 1 回分の本文と出力が収まらない (1 ページ分も入らない)

## 必要な機能

bannzai が 2026-11-18 に、この一覧のとおりでよいと決めた (「決めたこと」の行)。対応は iOS だけで始める。本文は端末の外に出さず、クイズは端末内のモデルで作る。取り込みは画面全体で、読書アプリを限定しない (動作を確かめる対象は Kindle を第一にする)。

- [x] 何を読むかを選ぶ: 読む前に、登録済みの本から選ぶか、名前を入れて新しく登録する
- [x] 出題の設定: 本ごとに、出題する問いの種類を選び、出題への希望を書ける
- [x] 読書を始める: iOS の画面共有の選択画面で画面全体を選び、取り込みを始める
- [x] 読書中の取り込み: 読書アプリを表示している間、背面でページが変わるたびに OCR して本文を残す
- [x] 読書を終える: アプリに戻って取り込みを止める
- [x] クイズ: 「読書を終える」を押した時に、読んだ範囲と、同じ本の前の読書から、端末内のモデルが問いを作る。問いの数は読んだ分量で決める。問いの種類は四択・要約の正誤・穴埋め (言葉を入力)・記述 (文で答える)
- [x] 回答: 問いに答えると、判定・模範の答え・根拠にした本文の引用が出る。穴埋めと記述は端末内のモデルが判定する
- [x] 履歴: 本ごとに、読書の記録・問い・自分の答えを見られ、問いにもう一度答えられる
- [x] 読書の記録と本の削除
- [x] 端末内のモデルが使えない端末・設定での案内 (クイズを無効にして理由を出す)
- [x] 取り込み中であることの表示と、初回の同意の説明
- [ ] 課金: 最初の版に入れる。月額・年額のサブスクリプションと買い切りを用意し、1 週間のトライアルを付ける。実装には RevenueCat を使う。値段は月額 500 円・年額 5,000 円・買い切り 20,000 円。トライアルは月額と年額だけに付ける。購入もトライアルもしていない利用者は、読書を 20 回まで無料で使える。無料の回数を使い切り、トライアル中でも購入済みでもない利用者が「読書を始める」を押すと、購入の画面を出す。購入の画面への入口は、設定の画面に 1 つと、読書を始めた後のホーム (本を選ぶ画面) に置く (bannzai の発言に無い条件と数え方は、「決めたこと」の 2026-11-19 の agent の行)。この項目は、bannzai が一覧を承認した後に足したもので、作る順のどこに置くかは決まっていない

## デザインの方向

- 画面の構成 (どの画面に何を置くか、画面のつながり) は、主要画面のモック (`documents/design/mock-2026-11-18/index.html`) のとおりにする (bannzai の決定。2026-11-19。「決めたこと」の行)。モックに無い部分の構成は agent に任せる (「agent に任せること」の行)。購入の画面をアプリのどこから出すかはモックに描かれておらず、bannzai が 2026-11-19 に決めた (「決めたこと」の行)。設定の画面はモックに無く、構成は agent に任せる
- 見た目 (色・文字・角の丸み) は、同じモックを見本にする: 白の地に濃い文字、強調は深い緑の 1 色、本から引用した本文だけ明朝、判定は青 (合っている) と橙 (合っていない) で、色に頼らず文でも書く。これは agent の案で、bannzai は見た目を採ったとは言っていない
- bannzai は、クイズらしく楽しい見た目 (原文「クイズ感があるようなUI」「ちょっと楽しい感じ」「バラエティ色があるというか」) を、機能ができた後に考えると決めた。案を作る issue: https://github.com/bannzai/doquiz/issues/44

## agent に任せること

- 主要画面のモックに無い部分の画面の構成と、文言
- 取り込みの間引き方 (同じページを繰り返し OCR しない、電池の消費を抑える)
- OCR の前処理 (縦書きの回転、ステータスバーやページ番号の除去)
- クイズに使う本文の選び方 (端末内モデルの文脈の大きさに収める切り方。同じ本の前の読書から渡す分の絞り方を含む)
- 問いの数の決め方 (読んだ分量から何問にするか)
- 穴埋めと記述の判定の出し方 (端末内モデルへの頼み方、判定の表示の文言)
- エラーの時の案内とテストの方針

## 用語

| 用語 | 定義 | 使わない言い換え |
| --- | --- | --- |
| 本 | 利用者が「何を読むか」として登録したもの。名前と出題の設定を持ち、読書の記録をまとめる | 書籍・タイトル |
| 出題の設定 | 本ごとに利用者が決める、出題する問いの種類と、出題への希望の文 | クイズ設定・プリセット |
| 読書の記録 | 「読書を始める」から「読書を終える」までの 1 回分。1 冊の本に属し、取り込んだページと、そこから作った問いを持つ | セッション・ログ |
| 取り込み | 読書アプリを表示している間の画面を doquiz が受け取ること | キャプチャ・録画・スクショ |
| ページ | 取り込んだ画面 1 枚から抽出した本文 | フレーム・スクリーンショット |
| 問い | 読んだ範囲から作った 1 問。問いの文・模範の答え・根拠の引用と、選択式では選択肢を持つ。種類は四択・要約の正誤・穴埋め・記述 | 問題・設問 |
| 模範の答え | 問いを作った時に決めた答え。選択式では正しい選択肢、穴埋めでは空欄に入る言葉、記述では答えの例 | 正答・正解 |
| クイズ | 読書 1 回の後に出す問いのまとまり。問いの数は読んだ分量で決まる | テスト |
| 回答 | 問いへの 1 回分の答え (選んだ選択肢か入力した文) と、その時の判定 | 解答 |
| 判定 | 回答が合っているとしたかどうか。選択式は模範の答えと同じか、穴埋めと記述は端末内のモデルが決める | 採点・スコア |
| 履歴 | 本ごとに、読書の記録・問い・回答を見て、問いにもう一度答えられる画面 | 復習 |
