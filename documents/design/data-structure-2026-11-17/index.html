doquiz 保存データの形

第 1 版から変えた点

順もらった意見第 2 版での形
1同じ本かを判定できると良い。または読む前に「何を読むか」を入力させる本の型 Book を足した。読む前に本を選ぶ (初めての本は名前を入れて登録する)。読書の記録は本に属する
2前回の記憶と合わせたクイズ保存する値は増やさない。問いを作る時に、同じ本の前の読書のページも読む
3問いは文量によって 3 問より多くてよい保存する値は変えない (問いの数は読んだ分量で決める)
4再出題は通常の流れに入れない。履歴の画面で答え直せるとよい読書の後の再出題をやめた。本ごとの履歴から問いにもう一度答えられる (回答が 1 件増える)
5「どのような出題が良いか」を「何を読むか」と紐づけて設定したいBook に、出題する問いの種類と、出題への希望 (自由に書く文) を持たせた
6穴埋めと記述に挑戦する穴埋めは空欄に入る言葉を入力する形にし、文で答える「記述」を足した。判定の結果を回答に保存する (端末内モデルの判定は後から求め直せないため)
7抽出した本文は残す第 1 版のまま (残す)
8取り込んだ画像は保存してもよさそう未決。下の「決めてほしい点」に、保存した時に増える負担を書いた

型定義 (Swift)

/// 本。利用者が「何を読むか」として登録したもの。
@Model final class Book {
    @Attribute(.unique) var id: UUID
    /// 登録した日時。
    var createdDateTime: Date
    /// 利用者が入力した本の名前。
    var title: String
    /// この本で出題する問いの種類。利用者が選ぶ。
    var questionKinds: [QuestionKind]
    /// この本の出題への希望。利用者が自由に書く (例: 「用語の定義を中心に」)。書いていなければ nil。
    var questionGuidance: String?
    /// この本の読書の記録。本を消すと一緒に消える。
    @Relationship(deleteRule: .cascade, inverse: \ReadingSession.book)
    var readingSessions: [ReadingSession]
}

/// 読書の記録。「読書を始める」から「読書を終える」までの 1 回分。
@Model final class ReadingSession {
    @Attribute(.unique) var id: UUID
    /// 読書を始めた (画面の取り込みを始めた) 日時。
    var startedDateTime: Date
    /// 読書を終えてアプリに戻った日時。読書中は nil。
    var endedDateTime: Date?
    /// 読んだ本。
    var book: Book?
    /// この読書で取り込んだページ。読書の記録を消すと一緒に消える。
    @Relationship(deleteRule: .cascade, inverse: \CapturedPage.readingSession)
    var capturedPages: [CapturedPage]
    /// この読書の後に作った問い。読書の記録を消すと一緒に消える。
    @Relationship(deleteRule: .cascade, inverse: \Question.readingSession)
    var questions: [Question]
}

/// ページ。読書中に取り込んだ画面 1 枚から抽出した本文。
@Model final class CapturedPage {
    @Attribute(.unique) var id: UUID
    /// 画面を取り込んだ日時。ページの並び順にも使う。
    var capturedDateTime: Date
    /// OCR で抽出した本文。
    var text: String
    var readingSession: ReadingSession?
}

/// 問い。読んだ範囲から作った 1 問。
@Model final class Question {
    @Attribute(.unique) var id: UUID
    var createdDateTime: Date
    /// 問いの種類。
    var kind: QuestionKind
    /// 問いの文。穴埋めでは空欄を含む文。
    var text: String
    /// 選択肢。画面に出す順。穴埋めと記述では空。
    var choices: [String]
    /// 模範の答え。選択式では choices のどれかと同じ文字列、穴埋めでは空欄に入る言葉、記述では答えの例。
    var modelAnswer: String
    /// 模範の答えの根拠にした本文の引用。回答の後に見せる。
    var evidenceQuote: String
    var readingSession: ReadingSession?
    /// この問いへの回答。履歴から答え直すたびに 1 件増える。
    @Relationship(deleteRule: .cascade, inverse: \Answer.question)
    var answers: [Answer]
}

/// 問いの種類。
enum QuestionKind: String, Codable {
    /// 内容の理解を確かめる問い (四択)。
    case comprehension
    /// 要約の文が本文と合っているかを答える問い (二択)。
    case summaryTrueFalse
    /// 本文の一部を空欄にした問い (空欄に入る言葉を入力する)。
    case fillInTheBlank
    /// 文で答える問い (記述)。
    case written
}

/// 回答。問いへの 1 回分の答え。
@Model final class Answer {
    @Attribute(.unique) var id: UUID
    var answeredDateTime: Date
    /// 利用者の答え。選択式では選んだ選択肢、穴埋めと記述では入力した文。
    var text: String
    /// 合っていると判定したか。選択式は模範の答えと同じか、穴埋めと記述は端末内モデルの判定。
    var isCorrect: Bool
    var question: Question?
}

第 1 版では答えが合っていたかどうかを保存しなかった。穴埋めと記述は端末内モデルが判定し、同じ答えでも後から同じ判定になるとは限らないため、答えた時の判定を isCorrect に保存する。選択式も同じ場所に保存して、読む側を 1 通りにする。正答率は保存せず、回答から数える。

利用者の操作と、読み書きするデータ

書く と 読む を操作 1 行ごとに並べた。

順利用者の操作書くデータ読むデータ
1何を読むかを選ぶ。登録済みの本から選ぶか、名前を入れて新しく登録する新しい本の時だけ Book を 1 件作る (title。問いの種類は 4 種類とも選んだ状態で始める)Book の一覧
2(任意) その本の出題の設定を変える。問いの種類を選び、出題への希望を書くBook.questionKinds / questionGuidanceBook
3「読書を始める」を押し、iOS の画面共有の選択画面で「画面全体」を選ぶReadingSession を 1 件作る (book、startedDateTime)なし
4読書アプリ (Kindle 等) に切り替えて読む。ページをめくるたびに背面で 1 枚取り込むCapturedPage を 1 件ずつ足す (前のページと本文が同じなら足さない)直前の CapturedPage (同じページかの比較)
5doquiz に戻って「読書を終える」を押すReadingSession.endedDateTimeなし
6クイズができるのを待つ (端末内モデルが、読んだ分量に応じた数の問いを作る)Question を問いの数だけ作るこの読書の CapturedPage.text、同じ本の前の読書の CapturedPage.text、Book の出題の設定
7問いに答える。選択式は選び、穴埋めと記述は入力する。答えると、判定と、模範の答えと、根拠にした本文の引用が出るAnswer を 1 件作る (text、isCorrect)Question
8本ごとの履歴を見る (読書の記録・問い・自分の答えと判定)なしBook と、その ReadingSession・CapturedPage・Question・Answer
9履歴の問いにもう一度答えるAnswer を 1 件足すQuestion
10読書の記録を 1 件消す / 本を消すReadingSession (本を消す時は Book) と、その下の全部を消すなし

決めてほしい点

1. 取り込んだ画像を保存するか (未決)

保存すると、OCR が読み違えたページを後から読み直せ、答えの後に元のページを見せられる。増える負担は次の 3 つ。

  • 写り込み。取り込みは画面全体なので、読書中に出た通知や、途中で開いた別のアプリの画面も入る。本文だけなら OCR が読めた文字しか残らないが、画像は写真やアイコンも含めてそのまま残る。
  • 端末の外に出る経路。アプリが保存したファイルは、除外の設定をしない限り端末のバックアップに入ると見ている (Apple の isExcludedFromBackup の文書 https://developer.apple.com/documentation/foundation/urlresourcevalues/isexcludedfrombackup は、ファイルをバックアップから除外する設定の説明で、既定でどの保存場所がバックアップに入るかは実機で確かめていない)。本文も同じだが、画像は書籍の画面そのものの写しになる。
  • 容量。1 ページ 1 枚で、読書 1 回で数十〜数百枚になる。1 枚の大きさは実測していない。

著作権と Kindle の規約の面では、本文の文字を残す時点で写しを端末に持っており、画像を足しても種類が変わるわけではない (どちらも位置づけは確かめきれていない)。ただし「書籍の画面を保存するアプリ」に近づくため、App Store で配る場合は審査での見え方が悪くなるおそれがある (仮説。審査での扱いは確かめていない)。

案: (a) 保存しない / (b) クイズを作り終えるまでだけ持ち、作ったら消す / (c) 残す (設定で消せる・バックアップから除外する)。保存する場合は CapturedPage に画像のファイル名を 1 つ足す。

2. 本の決め方は「読む前に選ぶ」でよいか

意見にあった 2 案のうち、読む前に利用者が本を選ぶ方を採った。取り込んだ本文から同じ本かを判定する方は、ページに本の名前が写らないため本文の似かたで推測することになり、間違えた時に別の本の記録が混ざる。選ぶ方なら混ざらない。判定は、後から「この本ですか」と候補を出す補助として足せる。

3. 出題の設定の中身はこの 2 つでよいか

「どのような出題が良いか」を、問いの種類の選択 (四択・要約の正誤・穴埋め・記述) と、自由に書く希望の文の 2 つにした。難しさの段階や問いの数の指定は入れていない。

この形にした理由

  • 穴埋めと記述の判定は端末内モデルに任せ、答えた後に必ず模範の答えと根拠の引用を見せる。判定が間違っていても、利用者が本文のどの部分の話かを見て振り返れるようにするため。
  • 前の読書と合わせたクイズのために、保存する値は足さない。同じ本の前の読書のページを読めば作れる。端末内モデルに一度に渡せる本文は限られる (文脈は 4K トークン) ため、前の読書から渡す分は絞る。
  • 問いの数は保存しない。読んだ分量から決め、作った問いの件数がそのまま数になる。
