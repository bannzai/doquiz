doquiz 保存データの形

端末内 (SwiftData) に保存する型は 4 つ。サーバーには何も保存しない。公開後に変えにくいため、実装の前に形を見てもらうためのページ。作成日 2026-11-17。

型定義 (Swift)

/// 読書の記録。「読書を始める」から「読書を終える」までの 1 回分。
@Model final class ReadingSession {
    @Attribute(.unique) var id: UUID
    /// 読書を始めた (画面の取り込みを始めた) 日時。
    var startedDateTime: Date
    /// 読書を終えてアプリに戻った日時。読書中は nil。
    var endedDateTime: Date?
    /// この読書で取り込んだページ。読書の記録を消すと一緒に消える。
    @Relationship(deleteRule: .cascade, inverse: \CapturedPage.readingSession)
    var capturedPages: [CapturedPage]
    /// この読書の範囲から作った問い。読書の記録を消すと一緒に消える。
    @Relationship(deleteRule: .cascade, inverse: \Question.readingSession)
    var questions: [Question]
}

/// ページ。読書中に取り込んだ画面 1 枚から抽出した本文。画像そのものは保存しない。
@Model final class CapturedPage {
    @Attribute(.unique) var id: UUID
    /// 画面を取り込んだ日時。ページの並び順にも使う。
    var capturedDateTime: Date
    /// OCR で抽出した本文。
    var text: String
    var readingSession: ReadingSession?
}

/// 問い。読んだ範囲から作った 1 問。3 種類とも「選択肢から 1 つ選ぶ」形で持つ。
@Model final class Question {
    @Attribute(.unique) var id: UUID
    var createdDateTime: Date
    /// 問いの種類。理解確認 (四択) / 穴埋め (四択) / 要約の正誤 (二択)。
    var kind: QuestionKind
    /// 問いの文。
    var text: String
    /// 選択肢。画面に出す順。
    var choices: [String]
    /// 正答。choices のどれかと同じ文字列。
    var correctChoice: String
    /// 正答の根拠にした本文の引用。回答の後に見せる。
    var evidenceQuote: String
    var readingSession: ReadingSession?
    /// この問いへの回答。再出題のたびに 1 件増える。
    @Relationship(deleteRule: .cascade, inverse: \Answer.question)
    var answers: [Answer]
}

/// 問いの種類。
enum QuestionKind: String, Codable {
    /// 内容の理解を確かめる問い (四択)。
    case comprehension
    /// 本文の一部を空欄にした問い (四択)。
    case fillInTheBlank
    /// 要約の文が本文と合っているかを答える問い (二択)。
    case summaryTrueFalse
}

/// 回答。問いへの 1 回分の答え。
@Model final class Answer {
    @Attribute(.unique) var id: UUID
    var answeredDateTime: Date
    /// 利用者が選んだ選択肢。Question.choices のどれかと同じ文字列。
    var selectedChoice: String
    var question: Question?
}

正解かどうかは保存しない。selectedChoice == question.correctChoice で分かるため。正答率と「理解が浅い問い」(最後の回答が不正解の問い) も保存せず、回答から数える。

利用者の操作と、読み書きするデータ

書く と 読む を操作 1 行ごとに並べた。

順利用者の操作書くデータ読むデータ
1「読書を始める」を押すなしなし
2iOS の画面共有の選択画面で「画面全体」を選ぶReadingSession を 1 件作る (startedDateTime)なし
3読書アプリ (Kindle 等) に切り替えて読む。ページをめくるたびに背面で 1 枚取り込むCapturedPage を 1 件ずつ足す (前のページと本文が同じなら足さない)直前の CapturedPage (同じページかの比較)
4doquiz に戻って「読書を終える」を押すReadingSession.endedDateTimeなし
5クイズができるのを待つ (端末内モデルが問いを 3 問作る)Question を 3 件作るこの読書の CapturedPage.text
6問いに答える。答えると正誤と根拠の引用が出るAnswer を 1 件作るQuestion (text / choices / correctChoice / evidenceQuote)
7次の読書を終えた時、前に間違えた問いがもう一度出る (再出題)Answer を 1 件足す最後の Answer が不正解の Question
8読書の記録の一覧を見る (日時・ページ数・正答率・本文の冒頭)なしReadingSession と、その CapturedPage・Question・Answer
9読書の記録を 1 件消すReadingSession と、その CapturedPage・Question・Answer を消すなし

この形にした理由と、見てほしい点

  • 本を表す型も、本の名前も持たない。画面の取り込みからは「どの本か」が確実には分からず、起票元のメモにも本を選ぶ・登録する操作は無いため。読書の記録は日時と本文の冒頭で見分ける。同じ本の複数回の読書をまとめて見たくなった時に足す。
  • 問いは 3 種類とも選択式にした。穴埋めを自由入力にすると、採点を端末内モデルに任せることになり、正誤がぶれる。選択式なら 3 種類を同じ形 (選択肢と正答) で持てる。
  • 取り込んだ画像は保存しない。本文の文字だけを残す。保存量を抑え、書籍の画面そのものを端末に溜めないため。
  • 抽出した本文 (CapturedPage.text) を残すか。残すと、後から問いを作り直せる。残さないなら、クイズを作った直後に CapturedPage を消す形になる。上の型は「残す」の形。
